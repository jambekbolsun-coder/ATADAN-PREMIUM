## 1. Что берём из Citadel

Citadel и ATADAN построены на одном стеке: Next 16, React 19, Tailwind 4, lucide-react. Поэтому оболочку и дизайн можно перенести почти напрямую. Данные и логику ATADAN (Postgres, свой вход, API) оставляем.

| Элемент Citadel | Как устроен | Что делаем в ATADAN |
|---|---|---|
| **Оболочка** | `app/layout.tsx`: сайдбар + верхняя панель + `<main>`; на телефоне нижнее меню и кнопка «+» | Та же оболочка, логотип и цвета ATADAN |
| **Сайдбар** (ноутбук) | ширина 256px, логотип, большая кнопка «Создать», пункты по группам с маленьким серым заголовком, внизу аватар → настройки | Три группы: **Работа / Маркетинг / Настройки** |
| **Верхняя панель** | заголовок экрана, «Назад» на вложенных экранах, поиск, колокольчик с счётчиком | То же. Уведомления уходят в колокольчик, отдельного пункта меню нет |
| **Нижнее меню** (телефон) | ровно 5 позиций, «+» по центру | `Главная · Работа · ＋ · Маркетинг · Настройки` |
| **Меню «＋»** | лист снизу (bottom sheet) со списком действий под роль | «Новая заявка», «Добавить трактор», «Платёж», «Расход» и т.д. (см. §5) |
| **Настройки** | сгруппированные списки как в iOS (иконка, подпись, стрелка) | Профиль, тема, уведомления, сотрудники, роли, журнал, сеансы |
| **Вход** | одна белая карточка по центру: логотип сверху, email, пароль, «Забыли пароль?», «Доступ только по приглашению» | Точно так же: без стеклянной панели, большого слогана и фоновых картинок |
| **Цвета** | токены `--bg --surface --surface-2 --border --text --muted --brand --good --warn --bad --info`, темы через `data-theme` | Те же токены, бренд — **зелёный ATADAN** вместо синего |
| **Компоненты** | `PageHeader, Card, Stat, Badge, Field, Empty, LoadError, Notice, Tabs, Pager`, таблица `.tbl`, строки `.row` | Переносим набор целиком. Все экраны собираются только из них |
| **Права в меню** | `NAV` с `perms`; пункт виден, только если есть право | Одна матрица прав для меню и для сервера (§7) |

Чего у Citadel **нет**, но нужно ATADAN: склад по VIN, лизинговые досье, маржа и себестоимость, каталог тракторов и запчастей. Эти экраны рисуем теми же компонентами.

## 2. Три части админки

```
АДМИНКА ATADAN
├─ Главная            сводка дня под роль (KPI + «что требует внимания»)
├─ РАБОТА             вся компания: продажи, склад, деньги, отчёты
├─ МАРКЕТИНГ          всё, что видно на публичном сайте
└─ НАСТРОЙКИ          я, команда, система
```

### 2.1 Работа

Цепочка процесса короткая и видна сразу: **Заявка → Сделка → Оплата → Выдача**.

| Группа | Пункт меню | Что внутри (вкладки) | Откуда сейчас |
|---|---|---|---|
| Продажи | **Заявки и сделки** | Новые заявки · Воронка (канбан) · Все сделки (таблица) · Лизинговые досье | `deals`, `site-leads`, `leasing-applications` — три входа сливаются в один |
| | **Клиенты** | список · карточка клиента (сделки, техника, платежи, история) | `client-base` |
| | **Задачи и встречи** | мои · все · календарь | `employee-tasks`, `meetings` |
| Склад | **Техника на складе** | реестр VIN · в пути · сроки хранения (aging) · карточка единицы | `inventory-units` |
| | **Закупки и поставки** | поставщики · заказы заводу · поставки | `suppliers`, `purchases`, `shipments` |
| | **Сервис** | обращения · гарантия | `service-cases` |
| Финансы | **Деньги** | платежи · долги клиентов и банков · расходы · кассы и счета | `payments`, `debts`, `expenses`, `financial_accounts` (сейчас не открыть) |
| | **Себестоимость и маржа** | по единице · по модели · по менеджеру | `costs` (сейчас недоступно) |
| | **Зарплаты** | начисления и выплаты | `payroll` |
| Отчёты | **Отчёты** | план/факт · модели · спрос и регионы · источники клиентов · экспорт | `control-*`, `finance` |

Пунктов в меню 10 вместо 22. Документы не отдельный раздел, а вкладка «Файлы» в карточках сделки, клиента и единицы, плюс поиск по документам.

### 2.2 Маркетинг

| Пункт меню | Что внутри | Откуда сейчас |
|---|---|---|
| **Каталог техники** | список моделей, цены, наличие, добавить трактор, фото и видео | `catalog` |
| **Запчасти** | каталог запчастей: цена, наличие, к каким моделям подходит | **новое** (сейчас нет) |
| **Публикации** | АгроЖурнал: черновик → опубликовано | `news` |
| **Акции** | акции и спецпредложения | `promotions` |
| **Лизинг** | общие условия · условия по моделям · калькулятор | `leasing`, `leasing-models` |
| **Страницы сайта** | сервис · FAQ и чат-бот · контакты | `public-service`, `faq`, `site-settings` |
| **Аналитика сайта** | посещения, интерес к моделям, заявки по источникам | `site-analytics` |

Пунктов 7 вместо 11.

### 2.3 Настройки

Экран-список в стиле Citadel. На ноутбуке открывается по аватару внизу сайдбара и по пункту «Настройки».

- **Профиль и аккаунт:** мой профиль · изменить пароль · сеансы и выход
- **Приложение:** тема (светлая / тёмная / системная) · уведомления (push, о чём уведомлять) · установка на телефон (PWA)
- **Компания** (видят владелец и директор):
  - сотрудники и приглашения (QR);
  - роли и доступы;
  - кассы и счета;
  - курсы валют;
  - этапы воронки;
  - журнал действий;
  - резервные копии.
- **Помощь:** инструкции · о приложении

## 4. Главная (сводка)

Ряд KPI сверху, ниже блок «Требует внимания». Содержимое зависит от роли.

| Роль | KPI | Требует внимания |
|---|---|---|
| Владелец / директор | выручка за месяц · валовая маржа · техника на складе (шт. и сумма) · долги к получению | заявки без ответа больше 15 минут · сделки, которые долго стоят на этапе · просроченные платежи · единицы на складе больше 90 дней |
| Менеджер | мои новые заявки · мои сделки в работе · мои продажи за месяц | мои задачи на сегодня · заявки без ответа |
| Бухгалтер | поступления за месяц · расходы · долги | платежи на подтверждение · просрочки |
| Маркетолог | заявки с сайта за 7 дней · топ моделей по интересу · конверсия | черновики публикаций · модели без фото или цены |

Каждая цифра кликабельна и ведёт в нужный список с уже применённым фильтром.

## 6. Дизайн-система (токены)

Перенос из Citadel, бренд заменяем на ATADAN.

| Токен | Светлая | Тёмная |
|---|---|---|
| `--bg` | `#f3f5f4` | `#0d1512` |
| `--surface` | `#ffffff` | `#141f1a` |
| `--surface-2` | `#edf1ef` | `#1b2923` |
| `--border` | `#dde4e0` | `#26372f` |
| `--text` | `#111a16` | `#eef4f1` |
| `--muted` | `#5d6b64` | `#97a89f` |
| `--brand` (кнопки, ссылки, активный пункт) | `#146b3a` | `#4cc183` |
| `--accent` (кнопка «＋») | `#146b3a` | `#4cc183` |
| `--good / --warn / --bad / --info` | как в Citadel | как в Citadel |

Цвета подбираются по контрасту не ниже 4.5:1. В Citadel это проверяет тест `themes.test.ts`, мы переносим его. Тёмные значения выше — черновые, их выверит этот тест.

**Остальные правила:**
- Шрифт один (Geist, уже подключён). Данные 14px, минимум 12px. Цифры моноширинные (`tabular-nums`), суммы выровнены вправо. Формат «2 860 000 с», «$29 500».
- Радиусы: карточки 16px, поля и кнопки 12px.
- Тени только у всплывающих листов и меню.
- Без стекла, градиентов, 4K-фонов и анимаций появления. Переходы не дольше 200 мс.
- Темы: Системная · Светлая · Тёмная. Дополнительные цветные темы — по желанию, позже.
- Стили админки уходят из `globals.css` (333 КБ) в отдельный файл админки и **не грузятся на публичном сайте**.

## 7. Техническая архитектура (как переписываем)

| Сейчас | Станет |
|---|---|
| Один клиентский компонент `AdminDashboard` на все 39 экранов | **Отдельный маршрут на каждый экран**, как в Citadel: `/admin/work/deals`, `/admin/work/deals/[id]`, `/admin/marketing/catalog` … |
| Мега-запрос `/api/admin/dashboard` грузит всё | Каждая страница получает на сервере только свои данные, с пагинацией |
| Навигация через `history.pushState` | Обычные ссылки Next (`<Link>`), у каждой записи свой URL |
| Права в трёх местах | Один файл `admin/nav.ts`: пункты меню + права. Сервер проверяет те же права |
| 15 слоёв CSS | Токены + компоненты из `ui.tsx`. Никаких `!important` |

**Что не трогаем без отдельного решения:**
- Таблицы базы данных и их содержимое. Новые экраны читают из тех же типизированных таблиц (`*_v2`, `crm_*`).
- API, которые уже работают. Новые экраны вызывают их, пока не переедем.

Чистка двойной записи и создания схемы при старте — отдельный этап 6, с резервной копией базы.

> Перед написанием кода сверяемся с `node_modules/next/dist/docs/`: в этой версии Next есть отличия (AGENTS.md).

## 9. Решения, которые нужны от тебя

1. **Этапы воронки.** Предлагаю 7 и «Проиграна»:
   `Новая → В работе → Расчёт / КП → Оформление (лизинг/договор) → Оплата → Отгрузка → Выдана`, плюс `Проиграна` с обязательной причиной. Сейчас этапов 11.
2. **Запчасти.** Только каталог в админке для учёта или ещё и раздел «Запчасти» на публичном сайте с ценами и заявкой?
3. **Чат и группы внутри админки.** Оставить (как раздел «Сообщения» в Работе) или убрать, раз команда общается в WhatsApp?
4. **Четвёртая кнопка нижнего меню.** Всегда «Маркетинг» или своя для каждой роли (бухгалтер — Деньги, менеджер — Сделки)?
5. **Темы.** Только светлая, тёмная и системная или ещё цветные, как в Citadel?
6. **Роли.** Оставляем 5: владелец, директор, менеджер, бухгалтер, маркетолог? Нужен ли сервисный инженер?
