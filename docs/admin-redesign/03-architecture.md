# Архитектура и логика админки ATADAN

Статус: **на согласование**. Документ заменяет разделы 2–5 из [02-plan.md](02-plan.md). Остальное (оболочка в стиле Citadel, этапы, порядок выката) остаётся в силе.
Макеты страниц: [mockups/index.html](mockups/index.html).

Главный принцип: **одна запись — одно место, всё остальное считается из неё.**
- Наличие на сайте считается со склада.
- Долг клиента считается из суммы продажи минус проведённые платежи.
- Себестоимость машины считается из закупки и расходов на поставку.
- Ни одно число не вводится руками в двух местах.

## 3. Жизненные циклы (статусы)

### 3.1 Машина (VIN)

```
Заказана ─► В пути ─► На таможне ─► На складе ─► Подготовка ─► Готова ─► Резерв ─► Продана ─► Выдана
                                       ▲  (PDI)                  │  ▲        │
                                       └──────── отмена продажи ─┘  │        └─► Возврат ─► На складе
   Повреждена / Брак ◄── (из любого до «Выдана») ──► Списана         └── новая продажа
```

| Переход | Кто / что делает | Что меняется автоматически |
|---|---|---|
| → Заказана | создан заказ заводу с моделью | на сайте у модели появляется «Под заказ, ~дата» |
| → В пути | поставка «Отгружено с завода» | сайт: «В пути, прибудет ~ETA» |
| → На складе | кнопка «Принять поставку» | себестоимость считается из закупки и расходов поставки; сайт: «В наличии N» |
| → Готова | «PDI выполнен» (чек-лист) | машину можно продать с выдачей сегодня |
| → Резерв | машину выбрали в продаже | на сайте минус 1 из наличия; резерв действует 14 дней (настраивается) |
| → Продана | продажа оформлена и оплачена (или разрешена выдача в долг) | выручка и маржа попадают в отчёты |
| → Выдана | «Выдать клиенту» с актом | начинается гарантия; машина появляется в карточке клиента |
| → Возврат | отмена после выдачи (только владелец) | обратные движения и возврат денег |

### 3.2 Продажа

```
Черновик ─► Оформлена ─► Ожидает оплату ─► Оплачена ─► Выдана ─► Закрыта
                │              │  ▲            │
                │              │  └ частичные платежи
                │              └─► Выдана в долг (только с разрешения владельца) ─► Закрыта, когда долг = 0
                └─► Отменена (причина обязательна; резерв снимается; деньги — возврат платежом)
```

- **Черновик** нигде не учитывается и не резервирует машину. Это для расчёта клиенту.
- **Оформлена**: машина в резерве, создан договор, появился долг на сумму продажи.
- **Ожидает оплату / Оплачена** — вычисляемый статус: оплачено = сумма проведённых платежей.
- **Закрыта**: выдана и долг 0.

### 3.3 Поставка (логистика)

```
Планируется ─► Отгружено с завода ─► В пути ─► На границе / таможне ─► Растаможено ─► Принято на склад
```

- На каждом шаге фиксируется дата. Если сегодня позже ETA, а поставка не принята, она подсвечивается как «Опаздывает».
- Расходы поставки (фрахт, пошлина, НДС на импорт, брокер, сертификация, разгрузка) можно добавлять на любом шаге.
- При приёме они распределяются на машины пропорционально закупочной цене. Вариант «поровну» можно выбрать.

### 3.4 Заявка (вместо CRM)

```
Новая ─► В работе ─► Продажа оформлена (связь с продажей)
                 └─► Отказ (причина: дорого, нет лизинга, купил у другого, не дозвонились…)
```

Заявка — только входящее обращение. Всё, что про покупку, живёт в продаже.

## 4. Пути продажи

Продажа одна, отличаются только способ оплаты и шаги до выдачи. Способ оплаты выбирается в форме продажи. От него зависят график и обязательные документы.

| # | Путь | Кто платит | Шаги | Когда можно выдать |
|---|---|---|---|---|
| 1 | **Полная оплата** (наличные / перевод) | клиент | продажа → платёж 100% → выдача | после 100% |
| 2 | **Предоплата + остаток** | клиент | продажа → предоплата → (машина едет / PDI) → остаток → выдача | после 100% |
| 3 | **Рассрочка ATADAN** | клиент по графику | продажа → первый взнос → график платежей → выдача → ежемесячные платежи | после первого взноса **и** разрешения владельца |
| 4 | **Банковский лизинг** (Айыл Банк, Элдик, РКФР, коммерческий) | аванс — клиент, остаток — банк | продажа → аванс → **лизинговое досье** (документы по чек-листу банка) → решение банка → договор с банком → оплата банка → выдача | после оплаты банка (или гарантийного письма — решает владелец) |
| 5 | **Гослизинг** (Минсельхоз, 6%) | банк по траншу | как путь 4, плюс ожидание транша; резерв машины длинный (60 дней) | после оплаты банка |
| 6 | **Запчасти / сервис** | клиент | быстрая продажа без VIN: позиции → оплата → списание со склада | сразу |

**Что делаем, если что-то пошло не так:**
- **Банк отказал** → кнопка «Банк отказал» требует причину. Варианты продолжения: сменить банк, сменить способ оплаты (на 1–3) или отменить продажу. Аванс клиента остаётся в продаже, пока не принято решение.
- **Клиент передумал после аванса** → «Отменить продажу» → система предлагает «Вернуть аванс» (платёж-расход) или «Удержать по договору» (доход с основанием). Резерв снимается.
- **Машины нет на складе** → в продаже выбирается **модель «под заказ»** вместо VIN. Продажа ждёт машину. Когда машина с этой моделью приходит, система предлагает привязать VIN.
- **Цена ниже прайса** → разрешено, менеджер ставит любую цену. **Ниже себестоимости** — не проводится (кроме владельца с причиной).
- **Клиент платит в другой валюте** → платёж записывается в своей валюте, пересчёт по курсу на дату платежа в валюту продажи. Курсовая разница идёт в отчёт.
- **Переплата** → платёж больше остатка не проводится. Система предлагает записать излишек как аванс клиента или вернуть.
- **Просрочка по рассрочке** → в «Долгах» корзины 1–30 / 31–60 / 61–90 / 90+ дней. Менеджеру и бухгалтеру уходит уведомление. Пени — по настройке, по умолчанию выключены.
- **Ошибочный платёж** → не удаляется, а **сторнируется** (обратная запись с причиной). Остатки касс и долги пересчитываются.

## 5. Каждая кнопка: что делает, что проверяет

Общие правила для **всех** кнопок:
1. Нет кнопок без действия. Если действие сейчас невозможно, кнопка неактивна, и подсказка объясняет почему («Сначала примите поставку»).
2. Каждое действие проверяется **на сервере** (права, статус, суммы). Интерфейс только помогает.
3. Повторное нажатие не создаёт дубль: кнопка блокируется до ответа, запрос идемпотентен.
4. Если запись одновременно изменил другой сотрудник, появляется сообщение «Запись изменил Нурлан в 14:02. Обновить?», а не тихая перезапись.
5. Опасные действия (отмена, сторно, списание) требуют подтверждения и причины.
6. Каждое действие пишется в журнал: кто, когда, что было, что стало.
7. После успеха — короткое уведомление внизу. После ошибки — причина рядом с кнопкой и «Повторить».

### 5.2 Склад и логистика

| Кнопка | Результат | Если не получилось |
|---|---|---|
| **Новый заказ заводу** | позиции «модель × кол-во × цена», валюта; машины в статусе «Заказана» (VIN пока пусто) | — |

| **PDI выполнен** | чек-лист, машина «Готова» | — |
| **Отметить повреждение** | статус «Повреждена», фото, претензия поставщику | — |
| **Списать** (только владелец) | машина / запчасть выбывает, стоимость — в расходы | — |
| **Запчасти: приход / расход / инвентаризация** | движение с причиной, остаток пересчитан | остаток не может стать меньше 0 → предупреждение и запрет |

### 5.3 Финансы

| Кнопка | Результат | Проверка |
|---|---|---|
| **Приход / Расход** (в кассе) | платёж с основанием: продажа, заказ заводу, расход, перевод между счетами | касса не уходит в минус без подтверждения владельца |
| **Перевод между кассами** | две связанные записи | одна валюта или курс обязателен |
| **Сторно** | обратная запись, причина | только бухгалтер / владелец; оригинал остаётся видимым |
| **Новый расход** | расход + платёж; категория и привязка (поставка, реклама, машина) | — |
| **Закрыть месяц** (владелец, бухгалтер) | записи за месяц нельзя менять, только сторно в новом месяце | — |

### 5.4 Маркетинг

| Кнопка | Результат | Связь |
|---|---|---|
| **Изменить цену модели** | новая цена прайса на сайте сразу; история цен | **уже оформленные продажи не меняются**; черновики предлагают обновить |
| **Скрыть / показать на сайте** | модель пропадает с сайта, но остаётся в продажах и на складе | скрыть модель, у которой есть машины в наличии → предупреждение |
| **Добавить модель** | карточка: название, класс, л.с., цена, фото, характеристики | slug уникален; без цены и фото модель нельзя опубликовать (только черновик) |
| **Добавить запчасть** | карточка для сайта и для склада одновременно | артикул уникален |
| **Опубликовать публикацию** | статья на сайте | без обложки и заголовка — нельзя |
| **Акция** | скидка на модель или запчасть на даты; на сайте плашка | при продаже цена со скидкой подставляется автоматически |
| **Условия лизинга** | ставки, взносы, сроки банков → калькулятор на сайте | — |

Наличие на сайте («В наличии 3», «В пути», «Под заказ») **не редактируется руками**: оно считается со склада.

## 6. Экспорт и импорт (Настройки → Экспорт и импорт)

### Экспорт
| Что | Формат | Кто |
|---|---|---|
| Любой список (продажи, клиенты, машины, платежи, расходы, каталог, запчасти) с текущими фильтрами | XLSX, CSV | у кого есть доступ к разделу; менеджер — только своё |
| Финансовый отчёт за период | XLSX | бухгалтер, владелец |
| **Полная резервная копия** всех данных | ZIP (JSON по таблицам + файлы) | только владелец |

Каждый экспорт пишется в журнал: кто и что выгрузил. Себестоимость и маржа в выгрузке есть только у тех, кому они видны.

### Импорт — 5 шагов
1. **Выбрать тип:** модели, запчасти, клиенты, машины (VIN), остатки запчастей, исторические продажи, платежи, расходы.
2. **Скачать шаблон** XLSX с примером и подсказками по колонкам.
3. **Загрузить файл** → сопоставить колонки (система угадывает по названиям).
4. **Предпросмотр:** «будет создано 120, обновлено 14, пропущено 3». Ошибки построчно: «строка 17: телефон в неверном формате». Строки с ошибками не загружаются.
5. **Загрузить.** Импорт получает номер, и его можно **откатить целиком** в течение 7 дней, если по загруженным записям ещё не было действий.

Дубликаты ищутся по ключу: VIN, артикул, телефон, № продажи. Для каждого импорта выбирается правило: «пропустить» или «обновить».

## 9. Главная (по ролям)

- **Владелец / директор:**
  - KPI: выручка за месяц, валовая маржа, машины на складе (шт. и сумма), нам должны.
  - Графики: продажи по месяцам, продажи по способам оплаты.
  - «Требует внимания»: согласования, просрочки, опаздывающие поставки, заявки без ответа.
- **Менеджер:** мои заявки, мои продажи в работе, мои долги клиентов, резервы, которые истекают.
- **Бухгалтер:** остатки касс, поступления и расходы за месяц, платежи без основания, долги по корзинам.
- **Маркетолог:** заявки за 7 дней по источникам, топ моделей по интересу, черновики публикаций, модели без фото или цены.

## 11. Изменения в базе данных

1. **Продажа без сделки.** Новая таблица `sales` (шапка) + `sale_items` (позиции: машина / запчасть / услуга). Поле `deal_id` убирается. Старые выигранные сделки переносятся в продажи один раз, со связью на исходную сделку для истории.
2. **Заявки** остаются в `leads`, плюс поле `sale_id` и причина отказа.
3. **Запчасти.** Новые таблицы `parts` и `part_movements` (приход, продажа, списание, инвентаризация).
4. **Поставки.** `shipment_costs` и распределение на машины (`unit_cost_allocations`).
5. **Курсы.** Таблица `fx_rates` (дата, валюта, курс, источник).
6. **Импорт.** `import_batches` для отката импорта целиком.
7. **Платежи.** Получают ссылку на продажу, а не на сделку; плательщик — клиент или банк.
8. Каждая новая таблица создаётся **миграцией**, а не при старте приложения. Перед миграцией делается резервная копия базы.

CRM-таблицы (`crm_deals`, `crm_tasks`, `crm_notes`, `deal_stage_events`) остаются только для чтения истории. Новые записи в них не создаются.

## 12. Принятые решения (5 ноября 2026)

| # | Вопрос | Решение | Как реализуем |
|---|---|---|---|
| 1 | Выдача по рассрочке | после первого взноса **и** разрешения владельца | кнопка «Разрешить выдачу в долг» только у владельца |
| 2 | Скидка | менеджер ставит **любую цену**, но **не ниже себестоимости** | лимита скидки нет; цена ниже себестоимости не проводится. Менеджер не видит себестоимость, видит только «ниже допустимой цены». Исключение — владелец с обязательной причиной (настройка «Разрешить продажу ниже себестоимости»: только владелец / никому) |
| 3 | Срок резерва | настраиваемый, **до 90 дней** | по умолчанию 14 дней (гослизинг — 60); менеджер может поставить любой срок до 90 дней; продление с причиной, но общий срок не больше 90 |
| 4 | Валюта договора | **USD и KGS** | валюта выбирается в каждой продаже; цена прайса хранится в USD и пересчитывается по курсу НБКР на дату продажи, если договор в сомах |
| 5 | Распределение расходов поставки | выбирают сами | в каждой поставке: пропорционально закупочной цене (по умолчанию) / поровну на машину / вручную по каждой машине |
| 6 | Пени за просрочку | **да** | в Настройках → Компания: ставка % в день, льготные дни, максимум % от долга; пени начисляются отдельной строкой долга, их можно списать (владелец, с причиной) |
| 7 | Трейд-ин | **нет** | способ оплаты не добавляем |

Поправка к §4 и §5.1: правило «скидка больше 5% → на согласование» заменяется правилом «цена не ниже себестоимости».
